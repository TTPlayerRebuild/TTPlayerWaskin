## 均衡器适配

宿主恢复的状态机区分通知次数：从命名预设收到第一次调整通知时只切换到自定义，后续通知才将 Current 复制到 Custom。原生控件按下滑块不通知，数值不变的移动不通知，松开时发送结束通知。

插件此前在按下、每次移动和松开时都发送命令。WSZ 的整数换算还会把零位按下误映射为 `+1 dB`；WAL 会把滑块中心重新移到按下位置。连续移动消息排队时，读取宿主状态也不能可靠去重，因为宿主可能尚未处理前一次命令。

本次调整：

- WSZ/WAL 按住均衡器、声道平衡滑块时保留鼠标在滑块内的偏移；原位按下不修改值。
- 按手势缓存最后排队的宿主数值，仅实际变化或松开时通知，避免过早覆盖自定义设置。
- WSZ 均衡器使用四舍五入映射；WAL 先换算为宿主 dB 值再去重。轨道方向、皮肤图像和 Winamp 布局继续由插件控制。
- WAL 的 Escape 与 WSZ 一样恢复本次拖动的初始值并结束捕获。脚本接管的鼠标事件不使用未初始化的拖动状态。
- MAKI 显式 `setPosition` 调用保留其通知语义；物理鼠标拖动的去重不吞掉脚本命令。
- 插件声道平衡复用宿主均衡器的状态转换函数，保留 Winamp 的 `-100..100` 精度。均衡器关闭时仍可调整平衡，频段调整继续被忽略。

## 标签写入期间的输入

插件使用注册窗口消息发送命令，不经过原生 `WM_COMMAND`，因此原生新增的保护不会自动覆盖插件入口。

现在在发送和接收两个阶段检查 `file_info_write_in_progress_`。写入前已排队的命令在写入期间派发时也会被丢弃；右键菜单的单独 FIFO 同步消费对应事件，避免写入结束后误弹出旧菜单或选中旧歌曲。写入期间收到的新菜单请求被消费但不排队。

歌词拖动、滚轮及双击全屏等直接回调同样受保护；尺寸变化、隐藏、取消捕获等清理消息仍正常处理。写入结束后，新操作立即恢复。

## 双击全屏

不另加插件私有设置，使用宿主 `Lyric/DoubleClickFullScreen` 与 `FullScreen/LastMode`。默认关闭；歌词右键菜单显示同一个开关。开启后从 WSZ 歌词内容或 WAL InlineAVS 歌词内容进入记忆的歌词、视觉或同屏模式；退出后恢复原皮肤与窗口状态。视觉区域、歌词编辑器和停止状态不触发歌词全屏。

标题区域、皮肤资源、插件 SDK 布局和 `ttp_maki.dll` 均无需修改。本轮不扩展 WAL 的控件支持范围。
